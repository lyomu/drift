**Created:** 22 October 2026
**Sources:** the supplied RSS Tennis News PRD and [repository audit](NEWS_RSS_REPOSITORY_AUDIT.md)
**Scope:** Tennis news ingestion, editorial control, and the existing Flutter News section. No scores, fixtures, rankings, odds, or other sports data.

**Status key:** `[ ]` to do · `[~]` in progress · `[!]` blocked by an external dependency · `[x]` verified complete.
**Priority key:** P0 must precede public launch; P1 required for the requested feature; P2 useful after the core workflow is proven.

Keep IDs stable in commits and handovers. Mark an item complete only after its **Done when** check is verified and record the test or evidence beside it. Existing functionality is listed as reuse, not tracked as new work.

## Launch gates and external decisions

1. **Rights:** No real publisher story or image goes public until the exact permitted uses are recorded and current. NEWS-004 is the external blocker.
2. **Safety:** The rights gate, SSRF/XML controls, idempotency, and admin authorization must pass before scheduled ingestion is enabled.
3. **Compatibility:** Existing saved stories and Flutter News routes must survive migration; client changes roll out after compatible API changes.
4. **AI:** Provider selection and permitted processing must be recorded; AI failure cannot stop imports. Automatic publication starts disabled.
5. **Ownership:** Publisher permissions, takedown contact, fallback artwork approval, and retention period need named product/editorial owners before launch.

## Progress log — 22 October 2026, first backend slice

- Added `NewsSourceRights` and an additive migration; existing active sources are paused by the migration. New sources are created paused even when an older admin client requests active.
- Added admin `GET/PATCH /platform-admin/news/sources/:id/rights`. Approval requires permission evidence, commercial headline/excerpt/cache rights, attribution, and a reviewer. The write endpoint requires both existing `CONTENT_MANAGE` and `PLATFORM_CONFIG_MANAGE` permissions. Revocation pauses a source, withdraws its approved stories, and writes an audit row in one database transaction.
- Public feed, detail, saved stories, and Home highlight now require an active source, approved current rights, and explicit publication. Publisher image URLs are omitted unless image reuse is allowed. Story approval and source activation reject missing rights.
- The RSS worker uses the shared Prisma service, due-time polling, and a database lease to sync rights-cleared active sources. It records run counts and source health, applies a cooldown, rejects DTD/entity declarations and unsafe item links, and uses a unique canonical URL hash to prevent duplicate inserts. Conditional GET, jitter, alerts, and broader parser fixtures remain open under NEWS-010 and NEWS-012–014.
- The News e2e suite now creates an isolated, rights-cleared fixture instead of depending on fictional seed stories. It adds a rights-revocation visibility check.
- Added News overview, source rights/test/sync controls, story moderation, and ingestion run history to the existing platform admin. Flutter News now pages with a cursor, caches the first page per signed-in user for offline use, uses a local fallback visual, and offers an external-browser path when in-app opening fails.
- Added [API and operations notes](NEWS_RSS_API_AND_OPERATIONS.md). Verified: Prisma schema validation, backend and admin builds, 76 targeted Jest tests, Flutter News analysis and 19 News tests. The live PostgreSQL e2e suite and migration application could not run locally because PostgreSQL on port 5434 and Docker Desktop were unavailable.
